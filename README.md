# 一起买菜 · Pantry Weave

把多道食谱合并成一张购物清单，按人数换算，勾掉家里已有的食材。

线上体验版：https://pantry-weave-recipes.jidongan150.chatgpt.site

站点已公开，访客无需邀请即可使用本机清单；登录后按用户保存云端清单。本次版本接入 Convex 云端开发环境。最新发布与公开访问证据见 `hackathon.md`。

## 中英文与安全检查

默认显示英文，右上角可切换 English / 中文，浏览器会记住选择。扫描结果的食材列表和展开编辑框也同步显示译名；单纯切换或聚焦不会修改源数据，只有实际输入才保存修改。常见菜名、食材、单位与备注同步切换；无法翻译的文字保留原文并提示。

截至 2026-09-21，68 项核心测试、类型检查和发布构建通过；此前 12 项 Convex 后端测试通过。真实云端测试确认了未变化食材的勾选保留、替代材料选择保存、人数留空、刷新读取、实时同步、过期修改拒绝和跨账户隔离。Puter 的实际模型识别、完整线上首次登录和真人首次使用尚未验收；程序测试不代表识别准确率。范围见 `SECURITY-REVIEW.md` 和 `VISION-SERVICE.zh-CN.md`。

## 当前版本

- 无须服务密钥即可体验两道示例菜、手动添加食谱、图片文字识别、调整人数、合并食材、勾选、复制和下载。
- 主入口使用现有 ChatGPT：复制一次识别说明，在 ChatGPT 上传图片，点击回复中的食谱链接，在网站核对后加入。链接在浏览器中校验，不会自动保存，也不会让网站访问聊天或使用订阅作为 API 凭证。生成链接失败时可粘贴完整 JSON 结果。
- Puter + Gemini 仅保留为折叠的实验选项；用户反馈账户创建失败，真实推理未验收。默认打开网站和上传本地图片不加载 Puter，不要求注册新服务。
- 未登录或未配置 Convex 时，清单保存在本浏览器，支持刷新和同一浏览器不同标签页；本机其他使用者也能看到，清理浏览器数据会删除它。存储不可用时明确提示刷新会丢失。登录后使用独立的 Convex 云端清单，不自动搬迁本机食谱。
- 登录使用 Sites 的 ChatGPT 身份；服务端签发短期凭证，Convex 校验后按用户隔离数据。同一账户重新进入仍能读取自己的清单。仅知道清单标识不能访问数据。
- Firecrawl 抓取公开食谱网页、OpenAI 提取结构化食材、AgentMail 发清单的后端代码已实现。尚未配置真实账户，也未进行实际抓取或邮件发送测试。
- 云端开发环境为 `https://peaceful-butterfly-641.convex.cloud`。公开访问、GitHub 仓库、真实网页导入、邮件联测与提交材料仍未完成。

## 图片导入

点击首页上传按钮直接选择图片，也可拖入图片；手机另有“拍照”入口。一次只接收一张图片，误拖到区域外不会跳离页面。支持英文、简体中文和 JPG/PNG/WebP（最大 10 MB、4000 万像素），处理后最多 3600 像素长边、800 万像素。结果先显示简短食材列表，点中某项才展开编辑。可直接加入清单，无须填写图片没写的用量或人数；未知人数的食谱保留原方用量，需要换算时再补充。加入后仍可编辑，保存后重算，只取消发生变化的食材勾选；另一窗口已修改时会阻止旧版本覆盖。

选图后显示预览，由用户选择识别方式：

- **AI 识别：** 点击按钮并授权后，将重编码后的图片发送至 Puter 和 Google Gemini，使用用户自己的 Puter 额度。原文件名及元数据不发送；图片最多 2400 像素长边、400 万像素。每次页面会话首次使用重新确认 Puter 账户。固定模型、输出上限与等待时限，不由本应用自动重试或切换更贵模型。取消不接收迟到结果，但无法保证退回已使用额度。第三方数据处理适用其政策，不能声称图片全程留在设备上。
- **本地识别：** 图片不上传。Tesseract.js 及语言数据从本站加载，首次使用需要下载识别资源，不需要账户或模型 API。有限词表可能遗漏稀有食材，复杂插画、多栏、手写和模糊照片效果有限。不会从无文字菜品照片猜配料。

两种方式均先核对再保存：仅确认后的结构化食谱通过既有账户权限写入 Convex，不在应用后端保存原图。另有手动粘贴 ChatGPT 完整识别回复的备用入口；该入口不会自动调用 ChatGPT。

原图、识别原文和框选工具折叠放在结果页最后；常规流程只需查看食材并加入清单。必要时可展开“原图与识别工具”框选食材区域，支持鼠标／触摸拖选及数值调整；重新识别会替换未保存的草稿。失败时仍可换清晰图片或手动填写。自动排版恢复会尝试还原同一行的食材与用量，不把不同行的零散数字拼成用量。

`prepare-ocr.mjs` 在开发和构建时从锁定依赖复制识别资源到忽略目录 `public/ocr`，不使用公共运行时 CDN。购物清单中的常见食材会自动分到蔬菜水果、肉蛋奶、主食干货或调味品；不认识的名称仍放在“其他”。

明确识别出的可选食材默认不加入清单，“水或牛奶”这样的明确替代关系可在折叠区二选一或跳过。未选材料仍保存在食谱里，日后可在编辑时重新选择。旧扫描记录中的自动可选备注会在编辑草稿中转为可选项，保存时才更新；复杂、未识别出的替代关系仍需人工核对。

核对页及可展开的扫描预览提供与主页面同步的中文／English 一键切换，切换菜名、常见食材、单位和提示，不覆盖识别原文或手动修改。常用词在本地翻译；复杂文字在浏览器支持时尝试设备内 Translator，首次可能下载语言包，30 秒后回退。未能翻译的内容明确保留原文，不能保证所有菜名和自由文本都有完整译文。

食材列表优先显示；需要时展开“保存这道菜的图片”，可保存单道菜的 PNG。卡片记录原食谱份数，不是按主页面人数缩放的合并清单。步骤候选的原文引述保留在编辑区，买菜界面和图片只显示简短的可选／替代提示。缺失数量保持未知。真实图片的测试结果及来源见 `OCR-CHECKS.md`，包括多栏遗漏和手写识别失败的记录。

主页面的“保存购物清单图片”会生成最终总清单 PNG：合并多道菜、按当前人数换算、排除勾选项，并保留未知用量与备注。弹窗支持中文／English，同步页面语言；修改人数、勾选项或语言后重新生成。下载文件可离线查看。图片在浏览器内生成，不需要模型 API；复杂自由文本仍可能保留原文并提示。

## 合并规则

已注明人数的食谱按“原始用量 × 目标人数 ÷ 原食谱人数”换算；未注明人数的保持原方用量，并与已换算的数字条目分开标记。克与千克、毫升与升可以换算；重量和体积、个数与重量不混合。食材身份与翻译复用常用词表，例如 onion／onions／洋葱会合并，pieces／个统一；带有不同处理说明的名称不做模糊合并。缺失数量保持未知，只有明确填写的“适量”保持该含义。

修改、增删食谱或更改人数时，只取消需求发生变化的食材勾选，其他勾选保留。比较合并后的数量、备注、是否按原方用量及未知数量的来源数；单纯改菜名不会清空勾选。已选及未选的替代项由后端校验，同一替代组至多选一种。文字、扫描卡和最终清单图片均排除未选材料。旧版本中此次首次归一化的名称／单位，其旧勾选键可能需要重新确认一次。

## 本地运行

需要 Node.js 22.13+（开发使用 Node.js 24）及 npm。

```sh
npm run install:ci
npm run dev
```

打开终端显示的本地地址。没有服务配置也可以使用体验模式。

连接 Convex：

```sh
npx convex dev
```

本地前端默认使用演示模式。CLI 自动生成的 `NEXT_PUBLIC_CONVEX_URL` 不会被这个前端读取。线上在 Sites 设置 `CONVEX_URL`；不要把本地 `127.0.0.1` 配置到在线站点。不要在本地开发服务器配置线上签名私钥，认证请求只能经过 Sites 可信入口。

数据库、网页导入和邮件调用运行在 Convex，前端运行在 Sites；可选 Puter 图片识别从浏览器直接调用。`convex/auth_public.ts` 只包含公开的验证密钥和签发者地址；私钥保存在 Sites 的 `PANTRY_AUTH_PRIVATE_JWK` 秘密变量中。将项目迁移到另一个站点时，应使用新的签名密钥、站点地址与匹配的公开验证配置。

## 服务配置

`.env.example` 只列出变量名称。真正的服务密钥须配置在 Convex Dashboard 的 Environment Variables 中；不要提交至 Git、放进前端变量或粘贴进聊天。

| 变量 | 用途 |
| --- | --- |
| `FIRECRAWL_API_KEY` | 抓取公开食谱网页 |
| `OPENAI_API_KEY` | 提取中文食材名称、用量和原食谱份数 |
| `OPENAI_MODEL` | 默认 `gpt-4.1-mini`，可改为支持严格结构化输出的模型 |
| `AGENTMAIL_API_KEY` | 发送清单邮件 |
| `AGENTMAIL_INBOX_ID` | 发件邮箱 ID |
| `AGENTMAIL_ALLOWED_RECIPIENTS` | 逗号分隔的测试收件邮箱；配置后才开放发送 |

内部清单标识由后端分配并绑定到经过验证的用户身份，浏览器不能选择其他人的归属。旧匿名清单不会被自动认领。邮件仍仅允许配置的测试收件人；开放任意收件人前需单独验证收件人权限。模型解析结果仍需与原食谱核对。
